## 如何复跑

在仓库根目录：

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 -m unittest discover -s packages/codex/skills/_shared -p 'test_expert_models.py' -v
python3 tests/host_smoke.py
python3 tests/host_smoke.py --platform codex --codex-wire
git diff --check
```

前两条只需 Python 标准库。宿主测试需要对应 CLI；没有 CLI 时会明确失败，不把“未运行”计为通过。`quick_validate.py` 是维护者环境中的 skill-creator 工具，不是发行包运行依赖；本仓库自带的结构检查同样验证必需元数据与引用。

`host_smoke.py` 给子进程指定全新的用户/配置目录，使用精简环境，不复制登录凭据、不连接个人运行中的 app-server，也不在真实配置里安装插件。临时目录由测试结束时清理。

`--codex-wire` 需要允许本机回环监听：临时 HTTP 服务只绑定 `127.0.0.1`，接收 Codex 启动时生成的原生工具定义并立即返回预设拒绝响应。检查目标是角色注册；这个有意的响应不是业务验证失败，也不是实际模型调用成功。该测试不调用外部模型、不执行模型生成的工具操作、不使用 API key。

## 适用范围与未验证项

- 已验证**安装、发现、资源完整性、更新/卸载边界和模型解析逻辑**，以及 [路由场景规则走查](migration.md#路由场景复核)。
- 没有用线上模型完成完整业务开发/bugfix；没有验证每位安装者的模型权限、提供方映射或所有项目工具。模型真实可用性仍由每次任务的策略核验。
- Claude 更新演练覆盖当前版本的更新命令与安装生命周期；Codex 另外用独立包的内容变更模拟升级，验证新文件生效和旧文件备份。未发布远端 2.0.0，因此未演练“从 GitHub 旧发布自动升级到新发布”的远端链路。
- 没有安装或运行推荐的第三方插件；推荐兼容性依据各项目上游文档，不能替代用户环境验证。
- Windows/Linux 和其他客户端版本未运行宿主测试；自定义 `CODEX_HOME` 布局不在当前自动安装支持范围内。

测试过程中发现的技能路径断言问题已修正：宿主会用 `r0/...` 别名展示路径，验证现在同时核对技能名、技能文件及临时根路径，避免将正确加载误判为缺失。最终结果不包含尚未解决的测试失败。
