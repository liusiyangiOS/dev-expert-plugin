## 路由场景复核

这是对最终规则的静态场景走查，不冒称已调用线上模型完成业务任务：

| 输入场景 | 两端应执行的行为 |
| --- | --- |
| 主动快修但无可靠根因/验证 | 拒绝准入，完整诊断；不先试改 |
| 局部行为快修修复后原问题仍在 | 首次失败立即升级，计数保留、同问题禁止回切 |
| 完整 bugfix 已失败一次，后来补丁看似很小 | 保持完整流程，不能降级 |
| 完整 bugfix 尚无失败、风险明确、局部准入成立 | 可以简化该实现节点；原 QA/debugger/review 保留 |
| post-coding 只读发现简单失败 | 报告缺陷，不自动改代码 |
| 相同旧失败、匹配有效且与本次无关 | 必要测试照跑，复用诊断，明确 `delta_pass` 与非零退出 |
| 失败文本相同但依赖/环境变化，或恢复后复发 | 重新调查，不放入永久免检名单 |
| 模型缓存过期、模型不可用或强度无法证实 | 核验或阻断；不静默降低质量要求 |

## 维护和发布

每端可以独立取出安装。仓库级文档与测试只用于维护，不是安装后的跨端依赖。修改某端后检查本端测试；改公共质量要求时分别落实两端并复核上表。

建议发布前：选择并补充许可证；确认版本号及实际最低宿主版本；在干净环境安装；运行相关测试；审查运行数据排除情况。没有发布授权时只交付本地变更，不创建 commit、tag 或 push。

- 增加三平台、两种 Python 版本的离线 CI；未提交/推送时不会替用户运行远端 CI。实测范围以 [验证记录](validation.md) 为准。

角色分工、快修准入与升级锁定、graph、必要验证、历史失败、模型分工与累计预算均保持；本次没有把“省时间”变成放宽质量条件。
