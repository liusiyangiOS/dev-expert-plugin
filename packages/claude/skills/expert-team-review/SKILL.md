# 专家团队全链路

执行前读取 [Claude 执行与路由](../_shared/expert-team-runtime.md)。本文包含完整流程，不委托其他平台加载正文。参数为空时沿用会话目标；对象/JSON 参数中的 task、bug、description、text 只作为任务数据，不作为代码执行。

调用参数：$ARGUMENTS

把用户当前目标、约束、已有授权和验收标准作为任务简报。采用“按风险选节点、按依赖执行、按证据交付”。

先读取 [平台与路径约定](../_shared/expert-platform.md)，按实际 Agent 环境解析路径、解释器与 shell；质量规则保持不变。

## 启动

完整读取 [执行约定](../_shared/expert-workflow-contract.md)、[角色与 graph 约定](../_shared/expert-role-contract.md)；创建专家前完整读取并执行 [模型策略](../_shared/expert-model-policy.md)，保留默认/疯狂模式、72 小时刷新与用户覆盖，并实际传入创建参数。

由主任务或 team-lead 担任唯一调度者，不再套一层团队。小改可走 dev→必要验证→code-reviewer；熟悉的多文件任务加 planner/qa；陌生技术、跨边界架构取舍加 researcher。用户明确要求全链路时按下列完整流程执行。

## 任务图

1. **调研（需要时）**：researcher 调查代码、已有能力和一手外部信息。跨模块按 graph 协议交付关系路径、源码证据与盲区；不为小改全量建图。
2. **计划**：planner 产出中文方案、任务依赖表、文件责任、接口契约、验收→测试映射、风险与回退。已有充分方案可以复用并核对缺口，不重复规划。
3. **实现**：dev 按 ready 节点执行；无依赖、无共享写入/环境冲突的任务可并行。公共契约先完成。合并后的集成验证仍是必要节点，不能用分支自测替代。
4. **测试**：qa 根据需求独立验收，返回证据和 `ROUTE`。允许补测试时先分配责任；完成写入后冻结审查对象。
5. **验收**：对同一快照并行派 code-reviewer 与 security-auditor。安全审查按实际风险确定深度；确认不适用可简短说明，不强行全库扫描。

## 有界回修

- `ROUTE=dev`：debugger 先根据失败证据定位，再 dev 最小修复、qa 回归；初次实现后最多两轮生产回修。
- `ROUTE=self`：QA 提供测试错误证据后仅修测试；本次执行累计最多两轮 QA 自修，不重置生产回修预算。
- `ROUTE=environment|inconclusive`：定位环境/偶发原因；有证据的可逆排障可继续，无法解决则标记阻断，不直接进入盲修。
- 测试预算耗尽时仍可做只读审查以收集风险，但不能交付或借审查回修绕开已耗尽的测试预算。
- 测试通过后的审查阻断允许一次定向修复→必要 QA 回归→受影响审查复核；修复导致测试失败或复审仍阻断则不可交付。非相关建议不进入强制回修。

每次相关变化使旧验证失效；复用未受影响证据。会话恢复与阶段状态按执行约定保存。

## 已知基线失败

验证前读项目已知失败记录；需要首次确认、复用诊断或判断失效时，执行 [历史失败协议](../_shared/expert-known-failures.md)。复用诊断不跳过必要检查；主理人负责持久化，QA 提供匹配证据，reviewer 核对本次适用性。

`ROUTE=pass`/`GATE=clean` 与符合协议全部条件的 `ROUTE=pass_with_known`/`GATE=delta_pass` 均可进入后续审查。本文“验证/测试通过”包括上述两种结果，但 `delta_pass` 最终只能称“本次改动验收通过，存在已知基线失败”。项目硬性全绿门禁、相关验收被阻碍、未知或变化的失败仍按原规则阻断。无关且有效的历史失败不触发生产回修或消耗本次修复预算。

## 最终交付

给出状态、图谱是否使用及限制、方案/变更、实际测试与审查结果、验收映射、回修计数和残余风险。只有必要测试和必须审查通过才标记“可交付”。提交/推送/部署沿用已有用户授权，技能本身不新增授权。

维护此技能时参考 [场景评估](../_shared/expert-evaluation-cases.md)。不加载或执行旧 workflow 脚本。
