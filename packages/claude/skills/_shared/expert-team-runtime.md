# Claude 专家团执行与路由

这是独立的 Claude Code 专家团。四个技能正文、八个角色、模型策略和共用规则全部从当前安装的 `${CLAUDE_PLUGIN_ROOT}` 读取；不读取或回退到其他平台配置。这里的“共享”仅指 Claude 专家团内部共用。所有文件均为普通文件，不使用软链接或硬链接。

## 入口与执行

| 用户目的 | 本地技能 |
| --- | --- |
| 需求开发、专家团协作 | [expert-team-review](../expert-team-review/SKILL.md) |
| 完整缺陷诊断与修复 | [bugfix-pipeline](../bugfix-pipeline/SKILL.md) |
| 编码后质量检查 | [post-coding-pipeline](../post-coding-pipeline/SKILL.md) |
| 主动快修或合格局部修复 | [quick-fix](../quick-fix/SKILL.md) |

主会话或已有 team-lead 是唯一调度者，完整读取选定入口及该入口要求的共用规则，不另起团队只为加载文件。读取本文件不会重新选择或启动另一个流程；保留当前入口、回切锁定与累计预算。相对路径按所在文件目录解析，`~` 表示当前安装者的主目录，不能写死个人用户名。

模型选择直接执行 [Claude 模型策略](expert-model-policy.md)，包括默认/疯狂模式、用户覆盖、按模式独立的 72 小时核验和真实调用证据。普通成员消费主理人已验证的选择；主理人直接启动时先核验，不委派尚未核验的成员绕过前置条件。

成员只完成分配职责，不递归创建团队。只读成员发现候选快修、缺陷或升级条件时返回证据，由唯一主理人决定。skill 由主会话/主理人调度，不调用旧 workflow 脚本，也不声称具备 Workflow 运行时的原生暂停/重放保证；恢复按 [执行约定](expert-workflow-contract.md) 核对快照、存活任务、预算和证据。

## 快修自动路由

- 主动 quick-fix 也必须先准入。开发/修复中出现有证据的局部低风险修复时，主理人读取本地 quick-fix 判断；不能凭改动行数少、报错位置明确或用户着急认定简单。
- 新功能实现不伪装成快修。post-coding 默认只读，简单失败不自动获得修复授权；明确“检查并修复”时按原迁移规则携带状态与预算。
- 完整 bugfix 中只有尚无修复失败、未确认复杂/高风险、未被锁定且全部准入成立，才能简化局部实现；原 QA 复现、debugger 根因门、最终 QA、必要审查保持。
- 准入被拒绝、快修第一次失败或发现复杂/不确定时，升级完整 bugfix，同一问题锁定、不回切。生产尝试、QA 自修和审查回修累计，入口切换、换人或恢复都不清零。
- 自动选择由当前宿主可见的技能描述和主理人判断触发，不是后台 hook，不保证每次自动命中。用户授权与必要验收不因自动选择改变。

## 证据、状态与缺失依赖

[角色与 graph 约定](expert-role-contract.md)、[执行约定](expert-workflow-contract.md) 和 [历史失败协议](expert-known-failures.md) 是本地必需规则。必要测试照跑，旧问题只复用诊断；未知失败、必要 flaky、阻碍验收和硬性全绿门禁不能豁免。最终区分 `clean`、满足条件的 `delta_pass` 与 `blocked`。

模型缓存仅用 `~/.claude/cache/expert-team/`；默认历史失败记录仅用 `~/.claude/state/expert-workflows/`。无项目约定时，任务 ledger 使用项目内 `.expert-workflow/claude/<task-id>/state.md`，避免与其他平台默认状态混用。项目已有记录可作为待核验的业务证据，但不会自动继承其他聊天的授权、已完成判定或剩余预算。

缺少本包文件就报告安装缺口，不从另一套平台目录寻找替代。Graphify、AST、LSP 等是可选工具；没有时按角色协议回退精确源码检索，不伪称图谱可用。无必要委派能力时报告缺口，不用自审冒充独立验收。

## 插件发行版的名称与路径

当前插件内的技能调用名为 `/dev-expert-plugin:<技能名>`，专家类型通常为 `dev-expert-plugin:<角色名>`。委派前核对宿主实际列出的角色类型，优先使用本插件命名空间，不能误用同名的个人旧角色。找不到必需角色就报告安装缺口，不换成自审。本文中的简称仍表示相同职责，不创建额外主理人。

`${CLAUDE_PLUGIN_ROOT}` 由 Claude 在加载 Markdown 时替换为当前版本安装路径；不要猜测缓存版本目录，也不要假定 Bash 环境已导出同名变量。读入附属 Markdown 后若仍包含该占位符，按入口已解析出的同一个插件根路径解释。相对 Markdown 链接从文件所在目录解析。只读源码在插件目录，模型缓存和状态仍在本端 `~/.claude/`，更新插件不能重置运行数据。
