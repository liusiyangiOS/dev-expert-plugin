# Claude 专家团动态模型策略

适用于 Claude 的四个技能及其创建/恢复的专家。主对话模型不变，不修改用户全局设置、角色定义、CLI 或其他平台配置。这里只适配模型与调用接口，不削减本地流程的质量门。

执行前按 [平台与路径约定](expert-platform.md) 核对当前环境；文中的 `~` 先解析为真实绝对路径，不能直接传给不支持展开的文件工具。

## 优先级与选择

1. 用户持续有效的显式模型/强度要求优先，并适用于后续修复、复审与升级。只指定一项时，另一项按以下规则解析。明确提供方/模型固定版本时保留，不自动换成新版本或别名。
2. 默认模式读取实际 `${CLAUDE_PLUGIN_ROOT}/agents/<角色>.md` 的模型配置；当前 `opus`/`sonnet` 等别名由宿主及提供方解析，版本更新无需在 skill 写死型号。主理人核对实际可用性，不能仅凭别名宣称全球最新模型。
3. 默认强度：dev-researcher 为 `medium`，其余七个角色为 `high`；如果外层已选更高强度则保留。用户明确要求的强度优先，不因快修、省 token 或工具限制自行降低。
4. 疯狂模式：QA、dev-researcher 保留默认角色分工；其余角色使用经当前官方资料及当前宿主可用性核验的最强通用开发模型，不永久绑定 `opus` 或列表第一项。无法核验或调用时报告具体阻断，不把次优模型冒称最强。用户模型覆盖优先于模式。
5. 宿主强制模型、环境覆盖、模型白名单或提供方映射可能改变实际结果；只查询必要的非敏感有效配置，不输出完整环境、认证文件或密钥。

## 每次检查与 72 小时核验

- 每次技能调用检查本次用户覆盖、CLI/提供方、相关有效模型映射、工具参数与可复用的已验证选择。主任务已验证且未失效时向各专家传递结果，不让每个角色重复查询。
- 验证元数据可由主理人原子保存至 `~/.claude/cache/expert-team/expert-model-cache.json`，仅供 Claude 专家团使用。记录 `schema_version`、非敏感宿主/提供方身份及 `modes.default`、`modes.crazy`。**每个模式分别保存** `verified_at`、`config_fingerprint`、验证状态、每角色请求模型/可核实解析结果/effort、官方来源和调用证据；必要时每个独立选择单独记录成功时间，模式不得比其最旧的必需选择更“新”。未核验的疯狂模式不得标已验证，用户临时覆盖不改默认分工。
- 缓存缺失、损坏、时钟异常、所选模式/必需选择超过各自成功核验后 72 小时，或提供方/相关配置/工具能力变化、实际调用拒绝选择时重新核验。刷新默认模式只更新默认证据，不能更新疯狂模式成功时间；全局 `updated_at` 只能表示文件写入，不用于判定模型有效期。旧模式缺少独立时间/指纹就视为未验证，不得只改时间戳续期。
- 核验来源为当前宿主实际支持信息及官方文档：
  - https://code.claude.com/docs/en/model-config
  - https://code.claude.com/docs/en/sub-agents
  - https://platform.claude.com/docs/en/about-claude/models/overview
  用当前版本实际支持的接口确认可用性；没有统一模型目录 API 时不编造接口。官方发布不代表账号可用；已有同会话成功调用可复用，需要时只做最小无副作用探测，不读项目或启动修复。
- 仅核验本次所需模式；未要求疯狂模式时不用为核验无关旗舰阻塞默认模式。显式指定模型时优先验证指定配置，不因无关默认缓存阻塞。核验失败不覆盖上次成功时间，不用过期证据宣称最新已确认。
- 刷新只在调用时发生，不创建定时任务、不自动升级 CLI、不改提供方映射。缓存无法写入时如实说明本次未持久化，不能承诺下次复用。

## 实际调用与阻断

使用当前宿主真实提供的 Agent 工具和自定义角色。将用户/策略解析出的 `model`、支持时的 `effort` 实际传参；不发送工具不支持的字段。没有相应参数时，只有角色定义和有效继承设置能证实满足要求才可使用；不能靠 prompt 中“你用 high”或 Agent 自报型号证明实际配置。

当前角色文件中的 `effort` 是默认值，不覆盖用户更高优先级要求或宿主强制环境设置。无法设置或证实满足模型/强度要求时，不启动该必需专家、不以主 Agent 自审代替独立 QA/review；可以继续授权的只读调查并报告阻断。真实调用被替换到其他模型也要重新核验，不能默认等价。

纯主 Agent 的机械快修保留当前主模型，明确动态策略选择的是专家；需要专家时才产生实际专家调用。复用存活专家仅限实际模型/强度仍匹配且任务上下文适用；升级、恢复或换入口不清除用户选择和修复次数。

各角色只消费主理人给出的选择和证据，不再次建立团队。交接至少包含宿主、模式、角色选择、实际参数/配置依据、已核实结果与限制；网络、认证、限流错误与模型不支持分开报告。
