# 专家工作流执行约定

本地协议版本：2026-10-20。四个入口共用，定义任务图、证据和恢复方式；模型分配继续使用 [expert-model-policy.md](expert-model-policy.md)，graph 与角色边界使用 [expert-role-contract.md](expert-role-contract.md)。

## 选择最小充分流程

每次只选一个入口，避免把全链路、bugfix 和 post-coding 互相嵌套导致重复验证。用户明确选定流程时遵循其要求；只读检查不能自动变成修复任务。任务小可省去无收益的调研/正式计划，但不能省略必要验收。专业领域工具按实际需要组合，不再限制“只能用一个 skill”；不要叠加两个调度流水线。

开始记录目标、验收、不做事项、实际仓库、基线选择依据、用户已有改动、真实构建/测试命令、可用角色/并发槽位与权限。不要默认基线是 main，不默认工作区干净。

## 任务图与单一调度

节点最少记录：`id / depends_on / owner / write_scope / acceptance / validation / status / evidence`。拓扑依赖无环；回修是有上限的状态迁移，不能变成无限环。

- 只有依赖成功且责任明确的节点才 ready。依赖 failed/blocked 的下游不能开工；独立工作可继续。
- 无共享写入和环境冲突才并行；契约先定、消费者后做。同一 checkout 的锁文件、生成物、数据库/端口要计入冲突检测。
- `主任务` 或 `team-lead` 二选一作为唯一调度者。成员不自行派新团队；并发数按宿主实际槽位，不写死更多。
- 写入结束并确认快照后再并行审查。QA 补测试也是写入，要先结束再审；审查期间不能另起 dev 修改同一对象。

## 证据与检查点

小任务用聊天中的紧凑表即可；多阶段/需跨会话恢复时，在项目现有任务记录位置保存 ledger。没有约定时用项目内 `.expert-workflow/<task-id>/state.md`（task-id 使用日期和安全短名；不自动提交该目录），不要为每个小改创建目录。

只由调度者写状态，记录：

- 目标、验收、基线、工作目录、模型策略解析结果和用户约束。
- 节点状态 `pending / running / passed / failed / blocked / skipped`；`skipped` 要有不适用理由，必须节点不能跳过。
- 文件责任、agent id、产物路径、关键决策和待解问题。
- 每次验证的实际命令、时间、退出状态/结果、环境、输入快照。
- 实现/QA 自修/审查回修计数，按入口上限统一计算。

**快照绑定**：有提交时记录 HEAD；脏工作区还必须记录相关 tracked/untracked 内容指纹（例如逐文件 SHA-256 清单，包含路径与删除项）。仅 HEAD 或 `git diff --stat` 不能识别未提交代码。包含会影响验证的测试、配置、锁文件和构建脚本；凭据只记录必要的脱敏环境身份，不复制内容。排除 ledger、日志、图输出等生成产物，避免状态记录导致无限失效。

验证/审查只覆盖其记录的输入。相关代码、测试、配置或环境变化后，将受影响结果标记失效并重跑必要范围；无相关变化不重复全测。不能拿改动前的通过证明最终版本。

恢复时读取 ledger 并核对实际 git/文件状态、产物和存活 agent。中断的 running 标成待核实，不假定成功；有效证据复用，不清零回修次数。提交、部署等副作用如已授权执行，先确认远端/本地状态，不能因恢复重复执行。该协议提供人工/agent 可恢复记录，不保证崩溃自动续跑或 exactly-once。

## 分流与收敛

QA 使用 `pass / pass_with_known / dev / self / environment / inconclusive`。验证前读取项目已知失败记录；疑似旧失败按 [历史失败协议](expert-known-failures.md) 核验并复用原因分析。`pass` 对应 `GATE=clean`，`pass_with_known` 对应 `GATE=delta_pass`，其余为 `GATE=blocked`。有效的无关旧失败可不重复排查，但必要验证和仓库/CI 硬门禁不得省略。环境故障不自动归罪业务代码；flaky 和未执行的必要测试不能算 pass。测试缺陷要有证据，不能为变绿删除断言。

`STATUS=done` 不等于 `VERDICT=pass`。审查按已定验收和真实风险判定；P0/P1 阻断，P2 的实际影响决定是否阻断并解释理由，P3/风格建议不阻断。相同问题合并；新发现真实缺陷仍须报告，可选加固不得无限扩张范围。

入口决定回修次数；外层计数覆盖 QA 自修、复审及换人，不能重启流水线归零。到达上限且有阻断就返回不可交付及证据；只有必要验证通过、所有必须节点完成且无阻断项才交付；`delta_pass` 交付必须披露已知基线失败，不能称全量全绿。预算不是停止已授权独立工作的理由。

## 模型与对外动作

创建专家前完整读取模型策略并实际解析/传参；角色 TOML 不固定模型。模型核验失败不能伪称已按策略运行，也不能擅自换档。无子 Agent 能力时可继续许可范围内的资料整理，独立验收要求须如实标记未完成。

提交、推送、部署遵循会话已有授权，阶段转换不重复询问。技能本身不授予外部动作；中文提交和用户的分支/worktree 约定继续生效。

## 条件快修路由

用户主动调用 quick-fix，或开发/bugfix 中出现有证据的局部低风险修复时，唯一主理人读取 `~/.agents/skills/quick-fix/SKILL.md` 完成准入。新功能不伪装成快修；post-coding 只读检查不因简单失败获得修复授权。

完整 bugfix 只有尚无修复失败、未确认复杂/高风险、未被锁定且全部准入成立，才能简化局部实现；原 QA 复现、debugger 根因门、最终 QA 和必要审查保留。准入拒绝、快修首次失败、复杂或不确定即升级完整 bugfix，同一问题禁止回切；跨入口沿用生产尝试、QA 自修、审查回修累计预算与有效模型选择。自动路由依赖当前宿主可见的技能和主理人判断，不是后台 hook。
