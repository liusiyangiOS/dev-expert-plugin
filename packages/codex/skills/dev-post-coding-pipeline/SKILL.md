# 编码后提交前质量门

默认只检查；构建/测试可以产生正常临时产物，但不得修改生产代码、测试、依赖锁文件或自动格式化。用户同时明确要求修复时才转入有界修复并重新检查受影响关卡。

“检查并修复”采用入口迁移，不嵌套调用：先结束失败的检查阶段，携带快照、证据及累计计数转到 dev-bugfix-pipeline，遵守最多三次生产尝试、两轮 QA 自修和一次审查回修；仅覆盖缺口等非业务缺陷可由主理人给 QA 明确写入范围，累计最多两轮。已有计数保留，超限不重新开始。修复完成后回到本质量门，仅补跑失效或未执行的关卡；再次失败不得通过入口往返重置预算。

先读取 [平台与路径约定](../dev-shared/expert-platform.md)，按实际 Agent 环境解析路径、解释器与 shell；质量规则保持不变。

## 启动

完整读取 [执行约定](../dev-shared/expert-workflow-contract.md)、[角色与 graph 约定](../dev-shared/expert-role-contract.md)；创建专家前完整读取并执行 [模型策略](../dev-shared/expert-model-policy.md) 并实际传参。

确认仓库/基线/完整变更范围（已暂存、未暂存、新文件）、用户已有改动和真实命令。记录输入快照，先收敛所有写入。只读角色的职责不代表工具自动只读。

## 关卡

1. **最低成本静态检查/构建**：执行项目真实需要的检查。纯文档等无构建需求时记录 `not_applicable` 和理由，换为适当校验，不臆造命令。新增/未知失败或失败妨碍必要验证时立即停止，`stoppedAt=build`。仅有效历史 lint/check 失败且满足下文 `delta_pass` 全部条件时可继续；不能将未成功的构建称为成功。
2. **QA 测试**：只读模式验证必要验收与影响路径，复用同快照/环境下已执行且完整的证据；缺证据才跑相应测试。跨模块按 graph 协议定位影响，并核验源码。输出 `ROUTE` 与真实计数；缺测试、环境失败或 flaky 必要路径均不能全绿。除满足下文历史失败协议的 `pass_with_known` 外，失败停止，`stoppedAt=test`，报告归属，本入口不自行回修。
3. **并行审查**：同一快照派 dev-security-auditor 与 dev-code-reviewer，按实际风险审查，不做无关全库审计。合并发现；阻断/未完成则 `stoppedAt=review`。
4. **最终快照核对**：确认被审输入未改变；有相关变化只重跑受影响关卡并复核。必要关卡均通过、必须节点无缺失且无阻断才标记“已通过提交前质量门”；`delta_pass` 必须附“存在已知基线失败”，不能称全绿或 CI 通过。
5. **提交（已有授权时）**：遵守中文提交、无 Codex Co-Authored-By 尾注等用户约定，只包含已确认的目标改动；不把无关用户文件一并提交。提交 hook 若改动了文件，重新核验受影响范围。没有提交授权则交付检查结果，不主动创建 commit；推送/部署各自沿用已有授权。

## 已知基线失败

验证前读项目已知失败记录；需要首次确认、复用诊断或判断失效时，执行 [历史失败协议](../dev-shared/expert-known-failures.md)。复用诊断不跳过必要检查；主理人负责持久化，QA 提供匹配证据，reviewer 核对本次适用性。

`ROUTE=pass`/`GATE=clean` 与符合协议全部条件的 `ROUTE=pass_with_known`/`GATE=delta_pass` 均可进入后续审查。本文“验证/测试通过”包括上述两种结果，但 `delta_pass` 最终只能称“本次改动验收通过，存在已知基线失败”。项目硬性全绿门禁、相关验收被阻碍、未知或变化的失败仍按原规则阻断。无关且有效的历史失败不触发生产回修或消耗本次修复预算。

## 最终报告

最终状态、输入快照、每关命令/结果或证据引用、审查结论、未验证限制；失败时给 `stoppedAt` 与具体归属，通过时说明是否已按授权提交。不能用“通过率高”替代必要验收全部完成。
