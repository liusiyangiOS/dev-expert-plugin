# 按需性能验证协议

仅在需求含性能目标、出现性能退化线索，或交付主张包含性能改善时读取；普通功能、文案任务不默认压测。本协议不提供压测引擎，不安装新依赖或固定绑定外部 benchmark skill。

## 先定义测什么

1. 明确用户路径/业务操作、起止事件与成功条件；先验证结果、状态、数据完整性。HTTP 200、进程退出或工具调用成功不能代替业务正确性。
2. 记录基线选择依据、目标与来源（用户验收、项目 SLO/历史基准或已确认需求）。缺少来源标明缺口，区分探索测量与达标验收；不自行发明统一延迟、流量倍数或 SLO。没有基线可先建基线，但不能声称改善。
3. 定义指标的单位、计时层级与边界：用户感知端到端、单请求、阶段耗时、吞吐、错误率、CPU/内存/IO 等按路径选择。批量总耗时、并发吞吐和单请求延迟分别报告，不互相替代；客户端计时与服务端计时也不混用。
4. `dev-planner` 将目标映射为可测验收、数据集、方法、资源/正确性护栏与停止条件；`dev-debugger` 用 profile/trace/受控实验沿调用路径定位瓶颈，区分测量开销和因果证据；`dev-developer` 仅优化已证实的瓶颈，保留业务契约和最小回归保护。

## 可比实验与原始证据

- 绑定前后源码快照（含相关脏文件、配置、依赖、测试和数据集身份）。测试二进制/服务时，尽实际能力核对实际运行版本、可执行文件/构建身份、健康/版本信息及哈希；构建成功不证明运行的是该构建。无法核实的身份与验证层级明确记缺口。
- 记录 OS、运行时/依赖、硬件或实例规格、电源/资源限额、后台负载、网络/服务位置和数据集大小/分布/种子。环境不同或无法控制时解释对比较的影响，不把异机单次数字直接归因于代码。
- 使用同一计时边界、数据、工具版本和负载模型做前后测；分别定义冷启动与预热、缓存命中/失效、并发/到达率、持续时间、超时与重试。不能把暖缓存新版本和冷缓存旧版本混在一张改善结论里。可复用项目已有 benchmark、profile 或实测可用的专项 skill，先核对其真实能力和副作用。
- 预先说明重复次数/样本单位及采样方法，保留每轮原始记录、错误/超时、离群点和缺失样本。异常需解释并同时给原始与筛选口径，不能为得到好结果隐藏或删样。重试不能抹掉首轮失败；测量顺序/噪声可能影响结果时，用交替或重复对照核查。
- p50/p95/p99 仅来自相应层级的原始样本，注明样本量、算法/工具和分布限制。小样本或聚合数据不足以支持尾部结论时标 `not_supported`；不能从均值推 p95，不能把批耗时或吞吐倒数包装为个请求尾延迟。不默认承诺统计置信度，显著性或置信区间需有适用方法与样本证据。
- 同时核对业务正确性、错误/超时及资源护栏，按既定需求评估以内存/CPU/并发或可靠性换速度的代价。护栏失败则不能按原验收通过。基线已存在失败也不豁免本次必要正确性验证。

## 授权与独立验收

只在获授权的项目、环境和负载范围实验。未知容量、共享环境或有外部副作用时先确定隔离、负载上限、持续时间和停止条件；未授权的生产实验、外部网络负载或数据修改不执行，交主理人补具体范围。已有充分授权不重复申请。post-coding 仅执行已授权且符合只读边界的验证，不因指标不好自行改代码、补测试或向生产施压。

`dev-qa` 从验收独立核对方法、业务结果和可比性，复用仍有效的原始证据，缺口才重测；不能只复述开发总结。reviewer 核验性能主张是否超出样本、环境、身份和正确性证据。

QA 的 `ROUTE/GATE` 沿用既有枚举：必要验收不可比或证据不足用 `ROUTE=inconclusive`，环境阻碍用 `ROUTE=environment`，已证实需生产修复用 `ROUTE=dev-developer`；这些结果均为 `GATE=blocked`。目标未达且原因待查时，QA 用 `ROUTE=inconclusive`，`dev-debugger` 只是下一步诊断负责人，不是 `ROUTE` 值；`fail` 也不是 `GATE` 值。正常通过仍按既有 `ROUTE=pass / GATE=clean` 或满足全部历史失败条件的 `ROUTE=pass_with_known / GATE=delta_pass` 报告。`PERF` 结论与 QA 门分别判断，不为了数字扩大修复范围或重置外层预算。

结论使用 `PERF=improved|not_improved|not_comparable|insufficient_evidence`（改善/无改善/不可比/证据不足），另报目标是否满足、护栏结果与未测。改善不自动表示达标，未测不等于无退化；只有可比的观测才可计算绝对/相对变化，噪声范围内或样本不足要保留限制。性能结论不替代外层 QA 的 `ROUTE/GATE` 或 review 的 `VERDICT`。

需要记录时使用 [轻量性能记录](expert-performance-record.md)，小任务可在对话/既有 ledger 内填写，不强制新建目录或提交实验数据。
