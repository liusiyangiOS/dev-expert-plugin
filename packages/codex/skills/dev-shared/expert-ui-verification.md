# 已有产品 UI 交接的实现验证

仅在收到已有产品需求、页面设计或产品审查记录时读取。验证实现是否符合已确认输入，回传事实；不重新裁决产品价值，不新建产品团队或反向自动路由，不依赖产品包安装。输入不足时记录缺口，向当前主理人澄清；已有业务授权持续有效。

- `dev-planner` 把需求/页面/路径 ID 和设计版本映射到实现任务与可测验收，保留原预期，不把当前 UI 当 oracle。
- `dev-developer` 按分配范围实现页面和状态，标出设计偏差、能力缺口及需要确认的取舍，不自行改写产品目标。
- `dev-qa` 按页面、关键状态（正常/加载/空/错误/禁用等实际适用项）、用户路径、视口及版本验证。可复用项目测试、浏览器/原生工具和获授权的专项能力；工具不可用或只查了源码就明确层级，不能称真实 UI 已还原。截图只能证明对应状态/视口，不代替交互或业务结果验收。
- reviewer 核验需求映射、偏差和回执证据，事实不符报缺陷，产品价值/设计取舍交当前主理人处理，不借审查扩验收范围。

回执复用已有 ledger/交接记录；每项最少记录：

| 字段 | 内容 |
| --- | --- |
| 需求/页面/路径 ID | 对应原交接项与验收 |
| 版本/输入快照 | 设计/审查记录版本、实现源码及实际运行身份（按能力核实） |
| 预期/实际 | 原预期、实测状态/交互与偏差 |
| 证据定位 | 测试、截图/录像或可重复步骤及实际结果 |
| 检查环境 | OS/设备、浏览器/运行时、视口、数据和状态 |
| 结论与未测 | 符合/不符合/证据不足；未覆盖项及限制 |
| owner/复验 | 实现/验证负责人，复验条件与下一步 |

仅包装/静态测试通过不等于视觉、交互或业务验收通过。多端分别回执，不能以单一桌面视口代表所有设备。
