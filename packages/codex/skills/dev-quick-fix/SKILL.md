# 快速修复

准确性优先，速度次之。作为专家团的轻量入口，由当前主任务或已有主理人调度，不另起团队；沿用用户授权、已有验收与模型选择。

先读取 [平台与路径约定](../dev-shared/expert-platform.md)，按实际 Agent 环境解析路径、解释器与 shell；质量规则保持不变。

## 入口与动态路由

- 用户主动调用与自动选择执行相同准入判断；“快修一下”、改动行数少、报错位置明确或着急，都不能免除判断。只读检查/分析请求不进入写入流程。
- 开始修复前，以及诊断完成、准备修改、验证产生新证据时重新判断。自动选择只在宿主提供本技能描述、主理人能读取本文件时生效；这是模型路由规则，不是后台 hook，不保证每次自动命中。
- 每个问题记录简短状态：`QUICK=eligible|rejected|escalated`、证据/风险、当前模式、累计生产修复/QA 自修/审查回修次数、是否禁止回切。复用已有任务记录，小任务可直接记录在对话中。
- 正在执行 `dev-bugfix-pipeline` 或专家团时，按下文“完整流程内使用”处理；不同时启动两套调度，不让成员自己再派团队。

## 修改前准入：全部有证据才 eligible

进行一次聚焦定位，业务代码保持只读；必要时在已授权、已分配的范围补最小复现测试并运行。新增红测不算生产修复尝试。逐项确认：

1. **期望明确**：预期来自用户需求、接口契约或可靠测试，不能把当前实现当作正确答案。
2. **根因成立**：同版本失败证据与实际代码路径能解释触发条件及修复机理；报错行、猜测、单次偶然通过不构成根因证据。
3. **范围可界定**：已核对直接调用方、相关测试和配置，能说明哪些行为必须保持。优先精确源码/搜索；必要时按 `~/.agents/skills/dev-shared/expert-role-contract.md` 使用 graph，不因图上缺边排除动态调用。
4. **验证可靠**：可实际运行原失败检查或能捕获原缺陷的行为回归，并验证相邻边界；所需工具、环境和独立验收可用。
5. **风险低且授权充分**：不涉及权限/信任边界、数据完整性/迁移、并发/偶发、跨模块根因、公共契约改变或无法界定的依赖/构建影响；不存在禁止写入或必须全流程的约束被撤销。

缺任一项或聚焦定位后仍不确定，标记 `rejected` 并进入完整 bugfix；不先试改一次。准入前的原始失败/红测是诊断证据，不是修复尝试失败。

## 两种快修执行方式

| 模式 | 执行与必要验收 |
| --- | --- |
| 机械性修复 | 只有确认不改变运行时行为、公共契约或依赖语义时，主 Agent 可最小修改、重跑原检查并核对最终 diff；无需机械新增业务测试。已有必需审查仍保留。 |
| 局部行为修复 | 主 Agent 或已分配 dev-developer 实现；必须有能捕获原缺陷的回归，修复前真实失败、修复后通过，并覆盖相关正常/边界/异常路径。独立 dev-qa 按需求验收、dev-code-reviewer 审查最终快照；可以复用外层已安排的角色，不以自测代替独立验收。 |

类型、导入、lint 报错不自动属于机械修复。类型断言、改默认值、异常处理、禁用规则或构建配置调整可能改变语义，须按实际影响重新准入。禁止弱化断言、吞异常、扩大容差、跳过检查来制造通过。

执行前按 [宿主模型策略](references/model-selection.md) 检查本次动态选择；不切换主对话模型。创建专家时读取共享角色约定并实际传入支持的模型参数，明确写入范围、已有协作者和验证要求；成员不递归委派。当前调度角色若禁止写业务代码，交已有 dev-developer，不借快修越权。

只修改根因相关位置，不夹带重构。每次生产修复尝试在修改前计数；一次围绕同一假设的内聚补丁算一次，失败后的新补丁是下一次，不能靠拆命令规避计数。

## 完整流程内使用

- 外层仍是唯一主理人。只有**尚无修复失败、未确认复杂/高风险、没有因快修被拒绝或升级而锁定**，且当前证据全部满足准入时，才能把局部实现按快修方式完成。
- 这仅简化局部实现和交接：完整 bugfix 的 QA 复现、dev-debugger 根因门、最终 QA、必要审查和预算仍有效；不把整个任务改判为“快修已完成”。用户明确要求完整流程时同样保留全部必要阶段。
- 复用仍有效的定位、测试和验收证据，不要求重新复现已确认的同快照事实。局部修复完成即返回外层待完成节点。
- 因快修拒绝、修复失败、复杂性或不确定性而升级后，对**同一问题**锁定完整流程，后续即使补丁看似很小也不回切。锁定和计数跨会话恢复、换人、换入口保持，不按文件拆分同一根因来重置。

## 验证、历史失败与交付

- 记录真实 cwd、命令/步骤、退出状态、失败/跳过项、环境和输入快照；最终证据必须对应最后一次相关修改。脏工作区不能只记 HEAD。必要时读取共享执行约定的快照规则。
- 行为回归优先现有可靠测试，缺少时补最小回归。无法建立可靠 red→green、必要路径 flaky、必要验证无法运行，均不按快修完成，移交完整流程定位。
- 验证前检查项目已有历史失败记录。疑似旧失败按 `~/.agents/skills/dev-shared/expert-known-failures.md` 核验；仅有效、无关且不阻碍本次验收的历史失败可复用诊断，必要测试不跳过。首次确认需本次改动以外的基线证据，不能凭“没改那个文件”豁免。
- 只有满足该协议全部条件才报告 `pass_with_known / delta_pass`，明确存在历史失败，不称全绿。新的、变化的或阻碍验收的失败要升级；项目硬性全绿门禁继续生效。历史记录由唯一主理人按共享协议持久化。
- 机械模式核对真实结果与 diff；行为模式还需独立 QA 和 review 通过。简述根因、改动、路由、实际验证、模型配置证据与限制。未运行或失败的必要关卡不能报告“已修复”。

## 立即升级完整 bugfix

以下任一发生即停止快修写入：准入不成立；复杂度/风险扩大；根因被反证；第一次修复后原问题仍在、出现新回归或必要结果无法确认；独立 QA/review 发现阻断；缺少必要独立角色或无法满足模型要求。没有“再快修一次看看”的中间路径。有效且无关的已知基线失败本身不算快修失败。

1. 记录 `QUICK=rejected|escalated` 和禁止回切，简短说明依据；已有修复授权内升级，无须重复询问。若用户另有禁止委派、只允许轻量或时间边界，遵守限制并报告阻断，不绕过。
2. 移交期望、复现/根因证据、源码与调用方、当前 diff/用户改动、测试快照和原始结果、历史失败匹配、模型配置及累计三类次数。
3. 主理人读取并执行 `~/.agents/skills/dev-bugfix-pipeline/SKILL.md`，需要时直接读绝对路径，不依赖宿主已注册该命令。若本就在该流程中，返回原节点，不重开入口。保留共享工作流的必要关卡；模型创建继续采用本包 Codex 模型策略，保留已验证选择和用户覆盖。
4. 沿用外层既有预算；独立快修转入 bugfix 时，其生产尝试计入 bugfix 总共最多三次（不是额外三次）。QA 自修与审查回修也累计，不因升级清零；已有预算更严时遵循更严者，耗尽则报告不可交付。
5. 原问题相关的测试缺陷、环境故障先按完整流程分流，不能继续猜改业务代码。补修复前证据使用隔离副本等非破坏性方法；保留用户改动，不 reset 活跃工作区。

共享流程/必要工具不可用则说明缺失与未验证项，不宣称已升级或修复。提交、推送、部署仍只依已有授权，本技能不新增权限。
