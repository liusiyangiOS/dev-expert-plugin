# 快修的宿主模型选择

每次进入技能时先识别实际宿主、用户本次及持续有效的模型/推理强度要求和外层已验证选择。快修不降低模型档位或推理强度，不修改主对话模型、角色文件、CLI、全局设置或共享策略。只复用同任务中仍有效且实际参数一致的选择。

## Codex

快修明确采用 `~/.agents/skills/dev-shared/expert-model-policy.md` 的默认/疯狂模式、用户覆盖、72 小时核验/刷新及真实委派参数规则，作为该策略的调用方，不编辑其文件。

- 进入时读取策略并按其要求执行共享 `expert_models.py status`；缓存失效时按策略核验官方资料和本机可用目录后 `refresh`，再 `resolve`。已有同任务有效解析可复用；用户指定模型等例外严格按共享策略。
- 纯主 Agent 机械修复仍使用当前主模型，明确动态解析只约束所创建的专家，不能声称主模型已切换。模型核验失败时可继续只读调查，不能借主 Agent 路径绕过用户要求或报告已满足动态模型策略。
- 有专家时，将解析出的 `model`、`reasoning_effort` 实际传给创建工具；需要时 `fork_turns="none"` 并提供完整任务简报。角色名称本身不决定模型，不硬编码 Sol/Terra 版本，不用 prompt 自报型号作证明。
- 升级完整 bugfix 后沿用有效解析及用户覆盖；到期或能力变化再核验，不能反复刷新或偷偷降档。

主理人负责派发，子角色不自行建团队。交接记录宿主、角色、请求的模型/别名、实际参数或配置依据、可核实的解析结果及限制；不靠子 Agent 自述推断真实模型。
